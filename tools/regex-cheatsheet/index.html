正则表达式速查指南

从基础语法、字符类、量词到分组断言与贪婪回溯，一份覆盖日志排查、表单校验、代码搜索场景的正则实战手册。

更新于 2026年8月7日 正则表达式文本处理速查
访问官网 ↗

工具简介

正则表达式（Regular Expression，简称 regex）是描述字符串模式的微型语言。无论做日志分析、表单校验、代码搜索替换，还是写爬虫、做数据清洗，它都是绕不开的基础功。配合 grep/sed/awk、编程语言内置 API、编辑器查找替换，能极大提升文本处理效率。

本篇按「语法 → 量词 → 字符类 → 分组断言 → 贪婪回溯 → 实战」梳理，并给出跨语言差异与避坑提示。

基础语法

1. 普通字符与元字符

普通字符（字母、数字、汉字）匹配自身；元字符有特殊含义，需用 \ 转义。

元字符：. * + ? ^ $ { } [ ] ( ) | \
abc        匹配 "abc"
a\.b       匹配 "a.b"（转义 .）
1\+1       匹配 "1+1"

2. 锚点（位置匹配）

^          字符串开头
$          字符串结尾
\b         单词边界
\B         非单词边界
^Hello          匹配行首的 Hello
world$          匹配行尾的 world
\berror\b       只匹配单词 error，不匹配 errors 或 errorLog

字符类

1. 自定义字符集

用 [...] 表示匹配其中任意一个字符；^ 在开头表示取反。

[aeiou]         匹配任一元音
[a-z]            匹配任一小写字母
[A-Za-z0-9]      匹配字母和数字
[^0-9]           匹配非数字
[-.]             匹配 - 或 .（- 放首尾不表范围）

2. 预定义字符类

.          除换行符外任意字符（单行模式下含换行）
\d         数字 [0-9]
\D         非数字
\w         单词字符 [A-Za-z0-9_]
\W         非单词字符
\s         空白字符（空格、制表、换行）
\S         非空白字符

量词

控制前一个元素出现的次数。

*          0 次或多次
+          1 次或多次
?          0 次或 1 次
{n}        恰好 n 次
{n,}       至少 n 次
{n,m}      n 到 m 次
go*gle         g, gogle, google, gooogle...
go+gle         gogle, google, gooogle...（至少一个 o）
colou?r        color 或 colour
\d{4}          4 位数字（如年份）
\d{3,}         至少 3 位数字
\d{2,4}        2 到 4 位数字

分组与引用

1. 捕获组

用 () 分组，可整体应用量词，也可被反向引用。

(ab)+           匹配 ab、abab、ababab...
(\d{4})-(\d{2})-(\d{2})   匹配日期，分三组：年、月、日
\1              引用第 1 个捕获组内容
(\w+)\s\1       匹配重复单词，如 "hello hello"

2. 非捕获组

(?:...) 只分组不捕获，不影响分组编号，性能略好。

(?:https?|ftp)://    匹配 http://、https://、ftp://，但不占捕获组

3. 选择分支

cat|dog|bird     匹配 cat 或 dog 或 bird

零宽断言（环视）

只判断位置不消费字符，常用于精准提取。

(?=...)     正向先行断言：右边满足
(?!...)     负向先行断言：右边不满足
(?<=...)    正向后行断言：左边满足
(?<!...)    负向后行断言：左边不满足
\d+(?=元)          匹配「100元」里的 100
\d+(?!元)          匹配后面不是「元」的数字
(?<=￥)\d+         匹配「￥100」里的 100
(?<!\$)\d+         匹配前面不是 $ 的数字

注意：JavaScript 在 ES2018 后才支持后行断言 (?<=) (?<!)，老旧环境不可用。

贪婪与非贪婪

默认贪婪（尽可能多匹配），加 ? 变非贪婪（尽可能少匹配）。

*?     非贪婪 0+
+?     非贪婪 1+
??     非贪婪 0或1
<.*>          贪婪：<a><b> 整体被匹配（.* 一路吃到末尾再回溯）
<.*?>         非贪婪：分别匹配 <a> 和 <b>

提取 HTML 标签时，非贪婪几乎是必备。

修饰符

i    忽略大小写
g    全局匹配（找出全部，而非首个）
m    多行模式（^ $ 匹配每行首尾）
s    单行模式（. 匹配换行符）
/hello/gi              // JS：全局 + 忽略大小写
const re = /\d+/g;
grep -iE "error|warn" app.log   # grep -i 忽略大小写，-E 扩展正则
sed -E 's/[0-9]+/N/g' file.txt  # sed -E 扩展正则

各语言用法

JavaScript

// 字面量与构造两种写法
const re1 = /\d{4}-\d{2}-\d{2}/;
const re2 = new RegExp('\\d{4}', 'g');

// 测试
/\d+/.test('abc123');           // true
'2026-08-07'.match(/\d+/g);     // ['2026','08','07']

// 替换
'a1b2c3'.replace(/\d/g, '#');   // 'a#b#c#'

// 提取捕获组
const m = '2026-08-07'.match(/(\d{4})-(\d{2})-(\d{2})/);
// m[0] 全匹配, m[1]=2026, m[2]=08, m[3]=07

Python

import re
re.findall(r'\d+', 'a1b22c333')         # ['1','22','333']
re.sub(r'\d+', '#', 'a1b2c3')           # 'a#b#c#'
m = re.search(r'(\d{4})-(\d{2})', '2026-08-07')
m.group(1)                              # '2026'
re.match(r'\d+', '123abc')              # 从开头匹配

Go

import "regexp"
re := regexp.MustCompile(`\d{4}-\d{2}-\d{2}`)
re.MatchString("2026-08-07")            // true
re.FindAllString("a2026-08-07b", -1)    // ["2026-08-07"]

实用技巧

1. 校验常见格式

邮箱：[\w.+-]+@[\w-]+(\.[\w-]+)+
手机号：1[3-9]\d{9}
URL：https?://[\w.-]+(:\d+)?(/[\w./?-]*)?
IP：(\d{1,3}\.){3}\d{1,3}
身份证（15或18位）：\d{17}[\dXx]|\d{15}

2. 编辑器里查找替换用捕获组

VS Code 查找替换（开启正则）：

查找：    (\w+)\((\w+)\)
替换：    $2 = $1($2)

把 foo(bar) 转成 bar = foo(bar)，$1 $2 引用捕获组。

3. 在线调试工具

写复杂正则时，用 regex101.com 实时调试，能看到每一步匹配与捕获，并自动解释语法。它还区分 PCRE / Python / JavaScript 等不同引擎。

4. 性能：避免灾难性回溯

嵌套量词（如 (a+)+b）在输入长串不匹配时，回溯呈指数爆炸，可卡死进程。改用原子组或具体化量词，或对用户输入限定长度。

5. 优先用字符串方法

判断「是否包含某子串」「是否以某串开头」时，用 includes / startsWith 比正则快得多、可读性也好。正则留给真正需要模式匹配的场景。

注意事项

  • 转义别漏：匹配 . + ? ( ) [ ] { } ^ $ | \ 时都要 \ 转义，否则语义完全不同。
  • 引擎差异：PCRE、JavaScript、Python re、Go regexp、POSIX BRE/ERE 语法不完全一致。比如 \d 在 POSIX BRE 里不支持，要用 [0-9]。
  • 贪婪陷阱：.* .+ 默认贪婪，提取标签、引号内容时容易多吃，记得加 ?。
  • 锚点别忘：校验整体格式时要用 ^...$ 包住，否则 ^\d{4}$ 才能保证整串是 4 位数字，\d{4} 会匹配 abc1234def 里的 1234。
  • 密码校验别过严：正则不适合做多条件组合校验（如「至少含字母数字特殊字符且 8 位以上」），用代码分步判断更清晰可维护。
  • 别用正则解析 HTML/JSON：嵌套结构用正则极脆弱，用专用解析器（DOM / cheerio / JSON.parse）。
  • .* 配 s 修饰符：要跨行匹配时记得开单行模式，否则 . 不匹配换行符。

实战案例

案例 1：从日志提取所有报错时间

日志格式 [2026-08-07 14:23:01] ERROR xxx，提取时间：

grep -oE '\[[0-9-]+ [0-9:]+\]' app.log

正则 \[[0-9-]+ [0-9:]+\]，\[ \] 转义方括号。

案例 2：批量把下划线命名改成驼峰

user_name → userName，在 JS 里：

'first_name_field'.replace(/_([a-z])/g, (_, c) => c.toUpperCase());
// 'firstNameField'

案例 3：校验强密码（代码而非纯正则）

「8 位以上，含大小写字母、数字、特殊字符」分步判断更清晰：

function isStrong(pw) {
  if (pw.length < 8) return false;
  if (!/[a-z]/.test(pw)) return false;
  if (!/[A-Z]/.test(pw)) return false;
  if (!/\d/.test(pw)) return false;
  if (!/[!@#$%^&*]/.test(pw)) return false;
  return true;
}

案例 4：提取 URL 里的查询参数

const url = 'https://a.com/page?foo=1&bar=2';
const params = Object.fromEntries(new URLSearchParams(url.split('?')[1]));
// { foo: '1', bar: '2' }

简单场景用内置 API，比正则拆更可靠。
